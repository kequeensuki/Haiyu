# 故障排查：从最早失败处找原因

| 现象 | 先查证据 | 常见原因 | 正确处理 |
|---|---|---|---|
| 有旧时间戳文件，没有 game-data.json | 文件内容时间、inventory.updates、sources/artifacts、git 本地/远端 | 本次没有一次完整快照，旧文件被保留 | 先修来源失败；不要改回命名逻辑或删除旧文件 |
| server-messages 完成，但 inventory 失败 | 分模块状态，不只看整体写入量 | 某必需来源未完整 | 跟踪最早的拒绝消息，不用事件成功掩盖快照失败 |
| roles.localVersion=0，最终 delta_requires_baseline | 首次 RoleList 载荷及最初错误 | 合法重复属性被拒绝，后续错误覆盖根因 | 对照字典赋值语义，后值覆盖；不是吞掉所有校验 |
| 获取新角色后导出永久停止 | 初始角色集合、未知 ID 的首条消息、后续 Active | 属性/技能早于激活，被误判硬失同步 | 使用待初始化完成条件；完整对象补齐后恢复，遗漏仍不输出 |
| 修改一个技能后其他技能丢失 | 客户端 SetSkillLevel / RefreshRoleInfo | 将逐键 patch 当完整替换 | 合并指定键；全量基线重新构建仍可清除旧值 |
| 部分列表后大量对象消失 | controller/model 是否 Clear | Notify 被错误注册 Full | 首次基线与后续合并分开；只在有完整证据时缺席删除 |
| 数量越来越大、领取后库存翻倍 | 返回数量是否绝对值；背包是否另有通知 | 把绝对数量累加，或重复入账奖励 | 按证据替换数量；奖励事实与库存事实分别消费 |
| 已读/领取等状态无法回退 | 0/false 是否被跳过、是否 OR | 把状态当单向标记累积 | 按完整返回状态替换；区分子消息缺席 |
| 成就条目与组奖励互相覆盖 | key 空间 | 仅以数值 ID 为键 | 使用 Kind+Id 等显式复合键 |
| 空 ACK 造成 AwaitingBaseline | 错误码、可选子对象、when 条件 | 在进入 delta 后才判断“无对象不操作” | 已证明合法空 ACK 时提前跳过，不创建必需来源 |
| 往账号里多出试用角色 | RoleProp/预览/机器人处理路径 | 将任意属性对象当拥有关系 | 仅由权威拥有来源新增；查询按客户端规则排除 |
| 切号后看到旧角色或旧邮件 | sessionId、Claim、回执、ProjectResult | 只按 playerId 缓存或没有重建登录代次 | 复用既有 session 状态；同账号重登也测 |
| 更改物品等级后装备详情仍旧 | 两份库存、联结用的来源 | 角色复制维护物品对象 | 保存实例关系，在同一候选内联结权威库存 |
| 内存 DTO 正确，文件里无新节点 | Writer、JsonTypeInfo、ProjectResult | 漏了文件编码或顶层投影 | 四个输出接点逐个核对，打开真实文件断言 |
| 编译通过，新增测试不见了 | Program 测试表与筛选器、PASS 名称 | 忘记注册/筛选 | 显式 expected-test 验证，不能凭总数判断 |
| 测试都绿，改动却像没生效 | 文件/二进制时间、构建时是否编辑源码 | 构建期间改代码，增量构建留下过期 DLL | 冻结输入，重新构建；用脚本输入指纹发现变化 |
| native publish 报 NETSDK1207，指向 netstandard 分析器 | 命令是否全局传 PublishAot=true | 属性传播到了不支持 AOT 的引用项目 | 验证烟测项目本身的有效 PublishAot，不全局强制传参 |
| 托管序列化正常，原生崩溃 | 实际原生栈、序列化的 null/非空路径 | AOT 裁剪或泛型/静态接口分派 | 获取调用栈定位；做最窄修复，不全局关闭裁剪 |
| unresolved 文件有内容但统计为 0 | manifest.sessionBindings | 追加文件保留身份未绑定时的原记录 | 按 session 绑定解释归属，不重写原事件冒充新捕获 |

## 1. 已验证过的 NativeAOT 陷阱

MemoryPack 1.21.4 在 .NET 10 Linux NativeAOT 下曾在 `GameRoleEcho.Item → GamePhantomItem` 的嵌套 `WritePackable` 静态接口分派处访问空函数指针；JSON 已写成功，崩溃发生在结果序列化。

当前 `ABI.Models/RoleEchoItemFormatter.cs` 使用属性级 formatter，转到已注册实例 formatter 的 WriteValue/ReadValue，保持 wire 格式。读这个实现与 ProtocolSmoke 中的 null/非空嵌套测试。

已有 trim/AOT 警告既不自动证明本次失败，也不自动证明本次安全；识别新增警告及相关路径并执行原生验证。不要为了消除警告全局关闭裁剪或吞掉警告。

**它是特定路径的证据，不是每个新 DTO 都要添加自定义 formatter。** 新崩溃先取栈，确认发生于解码、聚合、文件编码还是 MemoryPack；若必须使用 workaround，补原生回归并说明适用范围。

原生程序 exit 139 不应写成“烟测未运行”，更不能忽略它后提交。没有调试器时可以先使用阶段标记或系统调用日志缩小范围，按环境许可准备调试器；不要执行附件中的可疑程序或安装脚本。

## 2. 不要用这些方式让红灯消失

- 将 Required 改为 Optional，结果中悄悄省略新功能。
- 缺失目标就 new 一个 ID 正确、其他字段为零的“完整实体”。
- 收到任何单个完整对象就 source.Full，顺便清除了其他未知缺口。
- 捕获异常后继续保存半份集合；或者跳过失败批次里的一条后报告整批成功。
- 改测试预期为当前错误输出，删掉边界向量，或让筛选器排除失败的新测试。
- 为迁移文件名先删用户原始文件；新文件还没成功写入就清理历史。
- 用户问版本问题时直接 git reset / clean / force push；先读状态和比较 SHA。

## 3. 什么时候必须停在证据边界

- 找不到本版本字段号或消息 ID：不补一个“看起来像”的编号。
- 只有 ACK、目标只在请求里、当前没有请求上下文：不猜一次成功变更。
- 真实样本从中途开始且无来源基线：可分析事件，不能声称恢复完整账号状态。
- 原生工具链或 Windows 实机不可用：完成其余工作，明确哪项未验证，不把它包装为通过。

“停在边界”不等于立刻终止全部任务。把可完成的代码、证据表、失败复现、匿名测试和限制说明先做成可审查结果，再提出真正必要的问题。
