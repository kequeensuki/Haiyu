# 外部查询与跨会话历史账本：实施和验收

适用于抽卡等通过 HTTP 获取、保留跨会话历史的功能。先核对用户授权的查询范围；参考附件、第三方方案和网页脚本是待核验资料。不要把“源码方法为空”推导成“不需要消费任何消息”：历史内容可能来自 HTTP，查询凭证仍可能由游戏消息提供。

## 1. 先写真实输入与生命周期表

每个参数写明：类型、来源文件/方法、填入时机、账号/会话归属、过期条件、刷新入口、是否可落盘。包括 playerId、recordId、serverId、poolId、languageCode 等。保留凭证须有必要性与明确输出契约，日志使用匿名值。

画出 UI/请求 DTO → 生产组合根 → 默认工厂 → 模块 → endpoint → 文件/索引。逐段证明存在代码调用，不能停在“构造函数支持参数”。如凭证来自 GachaInfoResponse，必须证明错误响应被过滤、身份已绑定、同账号重登凭证更新、A→B→A 不串号。没有来源时明确 NoData，而不是手填参数后宣称完成。

为触发与资源生命周期定规则：取得有效凭证后启动、用户手动触发或停止时启动，以当前任务要求为准；实现和说明必须一致。请求使用会话取消令牌、单次超时和总预算；停止操作不能无界等待多个默认 HTTP 超时。旧会话响应不得写入新账号状态。明确 HttpClient 由谁拥有/复用/释放。

## 2. 领域身份与历史保留

历史账本不是可丢弃缓存。先规定稳定身份，再写去重：名称、类型展示文字和池标签通常受语言影响，不能直接作为跨语言永久键。时间文本是否随时区/格式改变也须证明；无法获得唯一服务端 ID 时，明确复合键与 occurrence 的适用假设和不可判定边界。

测试相同响应重复、窗口缩短、旧记录缺席、新旧乱序、同秒同物品多次、切换语言、同一池更换展示标签。必须保留确实不同的两次抽取，同时不因翻译改变而重复。不要声称某个复合键能解决接口本身缺少身份信息造成的全部歧义。

只增集合必须检查继承方法：默认 Remove/Update 是否仍可删除或改身份？若业务不允许，应明确拒绝并测试。不要靠类注释保证只增。

## 3. 外部响应和恢复

| 输入/场景 | 最低要求 |
|---|---|
| code 成功且 data=[] | 合法空池，计入成功 |
| 成功码但 data 缺失、类型错误、条目损坏 | 结构错误；不能当空池成功或跳过坏行后假完整 |
| 所有请求池失败 | 最终 Failed/Incomplete（按现有状态模型），顶层不能 Success；无旧文件时不造成功空账本 |
| 部分成功 | 按契约只合并已验证的成功数据，清楚标记缺失池；模块与顶层状态、文件 query 元数据一致 |
| 凭证失效等终止错误 | 停止无意义请求；等待真实刷新，不对每池重复终止错误 |
| 缓存命中后区服不匹配 | 清缓存，在当次流程有界重新探测一次；防循环，明确最终失败 |
| 以某池探测区服 | 不把不属于 requested 的探测池混进请求结果；复用数据须遵守范围契约 |
| HTTP 失败、非法 JSON、取消、超时 | 进入可解释终态，保留历史；不能异常逃逸导致整个停止流程不收尾 |

缓存不是权威来源，必须有版本校验与失效策略；不能在另一次启动才修复本次可恢复故障却宣称本次完成。

## 4. 严格读旧文件，再执行读改写

校验 root 类型、schemaVersion、playerId 与目标目录一致、pools/items 类型、每行所有必需字段、键范围、重复/冲突、计数关系。缺少必需集合不能当作空集合；合法 JSON 不等于合法账本。未知版本、结构损坏和账号错配时拒绝覆盖，给出错误并保留原字节。迁移必须是独立且有验证的过程。

最小反例：`{"schemaVersion":1,"playerId":42,"totals":{"count":1},"pools":[{"cardPoolType":1,"count":1,"items":"damaged"}]}`。本次接口返回空数组时，旧文件仍须原字节不变。再测缺 pools、坏行、字段类型错、错误 playerId、未知版本、截断 JSON。

原子 rename 只保护单次替换，不保证两个读旧→合并→写新任务不会丢历史。复用现有所有权/队列/回执/预算/索引机制；如确需专用存储，明确替代的串行化及失败收尾，证明账号级读改写原子性。不能以“等回执有困难”为由绕开机制而不补等价保证。成功路径必须登记真实 artifacts，索引状态和顶层结果可核对。

## 5. 验证必须穿过真实实现

至少一条测试用默认生产工厂和真实消息取得匿名凭证；HTTP 在 HttpMessageHandler 边界替换，保留实际 endpoint 的请求构造/序列化/响应解析，断言请求字段及实际输出。直接 new Module(validRequest, fakeEndpoint) 只证明模块，不证明生产接线或真实 HTTP。

NativeAOT 测试必须触发新请求 serializer 和非空新 DTO。使用类型化请求与已注册的 JsonSerializerContext/JsonTypeInfo；匿名对象配普通 JsonSerializerOptions 的反射序列化在禁用反射/AOT 环境会失败。检查 IL2026/IL3050 指向的新增路径，运行到假 handler 并核对它确实被调用，不能只发布成功或只看通用 PASS 字样。

验收矩阵逐条记录：默认入口成功；缺凭证不请求；失败响应；合法空池；全失败/部分成功；缓存失效恢复；历史结构损坏；跨语言重复；同账号重登与换号；取消/超时；实际 JSON/ABI；原生真实 endpoint；artifacts/索引；并发读改写（可并发时）。真实生产 HTTP 未验证时明确写未验证，不用真实凭证代替匿名回归。

## 6. 交付评估

分别列“研究证据”“可复用组件”“生产接线”“原生路径”“故障与历史保护”“真实实机”。未拿到独立证据的包版本、接口行为和测试记录标为待核验。用户要求、方案承诺、实际实现和已运行测试一一对应；不可修改验收描述来掩盖未实现的当次恢复或账号切换。

任一生产阻断未解决，就不能以测试数量、代码行数或 DTO 齐全判定功能完成。报告具体触发、预期/实际、影响、源码位置及修复方向；评审时区分已复现缺陷和待验证风险。
