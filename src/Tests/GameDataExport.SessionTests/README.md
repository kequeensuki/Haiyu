# 游戏数据导出生命周期回归

从仓库根运行（.NET 10）：

```sh
dotnet run --project src/Tests/ABIRuntime.TransportTests -c Release -- --game-data-export
dotnet run --project src/Tests/ABIRuntime.TransportTests -c Release -- --transport
dotnet run --project src/Tests/GameDataExport.SessionTests -c Release
```

第一组使用真实 ABI 实现，覆盖 RSA/AES、压缩、半帧、重登换钥和切号、112 重传、缺口超时和缓冲上限、目录故障恢复重试，以及真实命名管道 Cancel→收尾→Result。

第二组验证共享 ABI 管道的依赖注入、序列化、大消息、并发及取消控制帧。

第三组链接生产 Launcher、Windows 启动适配层和 ViewModel 源码。`UiBoundaries.cs` 只替代 Windows 宿主边界、语言查询、ViewModel 基类及 Shell API；不启动真实 WinUI。覆盖就绪/失败/超时、停止终态、会话复用、每会话运行状态 watcher、等待密钥超时及取得密钥后持续监听、自动会话窗口接入，以及窗口释放后的弱引用回收。窗口状态通过受控 SynchronizationContext 调度。

这些检查不代替 Windows 下的 NativeAOT 发布、Npcap 真机抓包和 XAML 验证。部署时须同时更新 UI 和 ABI 包，并重启旧宿主：进度模型尾部新增了显式的 CaptureReady、HasDataUpdate、SessionKeyAcquired 信号。

密钥超时回归使用可推进时钟检查真实 30 分钟边界：未启动游戏不消耗期限；运行中无握手，或有握手但无密钥，到期均停止并释放全部接口及网络事件订阅；成功取得密钥后推进一小时仍继续监听。

## 本次修复范围

- 新的有效 112 原子换钥并隔离旧快照；相同 112 重传不清空快照，失败协商保留旧密钥和历史文件。
- 只有网卡启动成功才发 CaptureReady；等待文案不代表就绪或业务活动。
- 每次会话自带运行状态 watcher；游戏启动前可等待，已观察到游戏运行后，其退出会触发停止。页面关闭不停止后台会话。
- KCP 单流最多保留 32 MiB / 32768 段，缺口等待最多 30 秒；超限/超时明确报错，禁止跨缺口拼帧。
- 写入失败保持待持久化状态，每秒重试最新快照，停止时再尝试收尾；成功写入后才推进已写版本。
- 窗口订阅状态并在释放时退订，不长期 await 会话；打开即同步已有监控状态。

增删改 Notify 支持按用户要求搁置，本次没有修改 MsgIdFilter 或增加任何增量通知类型。

## 多接口捕获回归

`--game-data-export` 同时覆盖：

- 按网卡 GUID 对应 Npcap 设备，只纳入已连接且具有有效 IPv4 的接口；不依赖网卡描述关键字。
- 多接口非阻塞公平轮询；收到普通 UDP 或看似握手的数据不会直接锁定接口。
- 协议层确认游戏数据后关闭其他接口；网络通知防抖 500ms 后恢复候选捕获。
- 重新枚举时先打开新接口，再移除已不可用接口；枚举失败保留现有句柄，捕获错误触发重试。
- 原连接无新握手，以及新传输连接无新 112 / playerId 时，沿用并验证已取得的会话上下文。
- KCP 序号去重、裸帧有界去重；重连验证前不写入候选快照，确认后淘汰同会话的旧传输，防止旧待写快照覆盖新数据。
- 停止后释放全部捕获句柄并退订网络事件。

Windows 上仍需验证真实 Npcap 驱动、接口 GUID 对应及非阻塞读取：先在有线连接导出，再拔线切无线，确认界面出现重新监听/接口锁定提示，输出仍归属同一个玩家目录且继续更新。链路类型目前支持 Npcap 的 Ethernet 格式（普通 Wi-Fi 连接通常采用此格式），其他格式会明确报告，不会静默忽略。

## 游戏退出与切号状态回归

- 启动本地鸣潮时，Launcher 订阅已有 GameEventPublisher 的 GameExit 事件，通知后立即请求收尾。监听属于 Launcher，页面切换不释放它；更换来源和应用退出时退订。
- 外部启动的游戏由 2 秒进程轮询兜底：开始抓包时尚未启动游戏会继续等待；观察到运行后再退出则停止。检测到游戏启动后开始独立的 30 分钟密钥等待计时；进程存活、普通流量和网卡变化不续期。成功解析密钥后结束该计时，随后持续监听直至退出或手动停止。
- 返回登录界面不会退出游戏进程，监控继续；文件写入使用 Monitoring 阶段，携带 playerId、输出路径、更新次数，并每 2 秒刷新状态。心跳不计作新的背包数据。
- 窗口通过 DispatcherQueue 调度，使用最新结构化状态显示账号和路径；旧连接的无关 KCP 包不会切换当前玩家。
- 测试使用真实游戏事件发布器，以及两次 RSA/AES 登录的完整导出链路；真实 WinUI DispatcherQueue / Npcap 驱动仍需 Windows 实机验证。请同步更新主程序及 ABI 包并重启旧宿主。

## RSA 私钥导入回归

- 导出窗口使用所属 `WindowSession` 的文件选择器，ViewModel 通过 `IGameDataExportKeyService` 调用独立的文件校验与凭据保存服务。
- 接受未加密的 PKCS#1 / PKCS#8 RSA 私钥 PEM，拒绝公钥、其他算法、加密或损坏的 PEM，以及过大文件；校验失败和取消都不写入凭据。
- 使用 `Haiyu/Secret/waves.kcp` 当前用户普通凭据；转换为 PKCS#8 DER 以适配 Windows 的 2560 字节上限，覆盖 2048 / 4096 位密钥。保存成功或失败后均清理临时私钥缓冲，不复制明文文件或记录密钥。
- 导出端使用实际 `SecretAccessor` 解析器读取 DER，同时兼容已有 PEM。保留环境变量 → 凭据管理器 → DPAPI 的来源优先级。
- 窗口覆盖选择取消、成功、失败、导入期间禁止启动、捕获期间禁止导入、选择文件时自动捕获启动，以及窗口关闭后不再调用导入服务。
- Windows 下额外使用随机临时凭据 target 做真实跨组件读写并删除；非 Windows 环境跳过这项原生验证，其余业务、解析器和 ViewModel 测试照常运行。

更新次数在同一次监控中按 playerId 独立记录：A→B 首次导出分别为 1 次，切回 A 后继续为 2 次；只有成功写入才累计，停止时的最终写入沿用相同规则。回归同时覆盖 UI 接收新玩家次数和旧连接数据隔离。

结束捕获的结果通过 ABI 返回按 playerId 去重的成功导出摘要，包含该玩家最近一次成功写入的四类数量、更新次数及文件路径。业务层维护摘要，窗口只格式化显示；关闭后重新打开窗口仍能展示本次汇总。后续账号导出异常不会丢失先前成功导出的摘要；同一玩家再次更新只替换自己的摘要，不重复列出。新建捕获会话重新开始汇总。新增 ABI 字段要求主程序和 ABI 包同时更新。
