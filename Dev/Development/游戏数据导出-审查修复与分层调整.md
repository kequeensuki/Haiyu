# 游戏数据导出：审查修复与分层调整

本次先修复功能缺陷并运行回归，再拆分 InventoryCaptureState。普通背包增删改 Notify 仍按此前决定搁置，未增加新的状态合成模块。

## 功能修复

1. 登录隔离不再依赖是否启用事件导出。LogoutNotify、LoginResponse、换钥及 BasicInfoNotify 使用统一身份边界；身份未确认时不能把新快照写给旧玩家。保留 BasicInfo 裸帧先于首次 KCP 登录确认的处理。
2. 组合导出分别保留快照与事件结果。快照写入失败不会被事件成功覆盖；某玩家未恢复的写入失败也不会被之后另一玩家成功覆盖。事件 manifest 的 completed 只描述事件文件，不能替代整体请求结果。
3. 校验业务帧 CRC；它独立于 KCP 数据报 CRC。压缩帧校验密文载荷，不包括已剥离的 OrigSize。失败帧不更新背包或确认连接，全量模式记录 crc_failed 和原始载荷。
4. 解密器由登录上下文持有，使用与释放在同一同步边界内；不共享宿主全局 transform，释放时清理缓存密钥。
5. 传输连接按服务端/客户端 IP、端口及 conv 区分，分配本次捕获内唯一的 connectionId。不同端点相同 conv 不再复用 SN 水位；登录继承关系仍单独管理。
6. 导出契约指定取消后等待最终结果或管道断开，其他 ABI 服务保留原有 5 秒取消宽限。Launcher 的单次停止等待仍有 10 秒上限，超时返回“后台仍在释放”，保持会话活动，最终确认前不开放第二个会话。进程强制退出仍可能留下 running/incomplete 产物，不能保证强退时完成写盘。
7. Exception 控制帧独立于 protobuf/解密流程处理，事件记录 errorCode，rawEncoding 为 transport_control，不将错误槽位当普通 CRC。

同时将 RSA 密文长度校验改为依据所导入私钥的 KeySize，覆盖 2048/4096 位有效密文；保存成功不再与加载器固定 256B 的能力冲突。修正 Core 中 DPAPI 的指针参数声明，与 ABI 的原生签名一致；真实 DPAPI 调用仍需 Windows 验证。

## 分层

```text
捕获 / KCP 重组
  → CaptureConnectionState：切帧、验证、解密调度、通用解析、消息分发
      ├─ GameSessionContext：密钥、登录身份、登录会话 ID、连接验证状态
      ├─ InventoryCaptureState：明文背包消息 → 四类快照与版本
      └─ IGameMessageObserver → EventExportSession：已解析消息 → 事件文件与统计
```

- InventoryCaptureState 不依赖 Npcap、FrameCipher、SessionKeyLoader、PlayerIdResolver 或事件写入器；其 Apply 方法只接收 msgId 和明文 protobuf。重连复制快照不复制传输重组状态。
- GameSessionContext 不持有背包与文件。退出登录后保留密钥，但暂不确认旧身份；停留在登录界面不消耗身份等待时间，新登录确认后才进入身份等待。初始会话密钥的 30 分钟期限仍由应用 Launcher 维护。
- PlayerIdResolver 移入 Session 命名空间。
- CaptureConnectionState 产出 MessageObservation，携带已确定的玩家/登录会话归属及通用解析结果。事件消费者通过接口订阅，不返回“是否有效”来决定核心登录行为。
- EventExportSession 不再调用协议解码器，不判断是否应复用旧玩家；只消费观察结果、绑定索引、写文件和累计统计。
- 页面和 ViewModel 的职责未增加，没有引入抓包、密码学或协议解析代码。

## 自动验证

从仓库根运行，使用 .NET 10：

```sh
dotnet run --project src/Tests/ABIRuntime.TransportTests -c Release -- --game-data-export
dotnet run --project src/Tests/ABIRuntime.TransportTests -c Release -- --transport
dotnet run --project src/Tests/GameDataExport.SessionTests -c Release
python -m unittest discover -s tools/tests -v
dotnet run --project src/Tests/GameDataExport.ProtocolSmoke -c Release
```

新增测试覆盖：两种模式复用密钥切号、CRC/压缩帧、没有密钥的 Exception、4096 位 RSA、并发独立解密器、组合导出写入失败、不同端点复用 conv、真实响应读取超过 5 秒后的收尾结果、纯快照消费者及没有事件消费者时的重连验证。旧合成流量补齐真实业务 CRC。

慢速收尾用例通过真实命名管道调用生产响应读取逻辑：模拟宿主在取消后 5.5 秒完成；Launcher 提前返回等待超时但仍 Active，5 秒后请求仍未结束，最终成功取得结果。它验证客户端协议时序，不代替真实磁盘性能验证。

协议 smoke 覆盖 RSA、AES、业务 CRC、身份、四类背包、事件消费者及 MemoryPack。Linux NativeAOT 发布及执行用于检查裁剪和 AOT 路径，不代替 Windows 发布或 Npcap 检查。

本次云端最终结果：21 组捕获/协议/消费者测试、5 组共享 ABI 测试、10 组会话/VM 测试及 7 项 Python 校验测试均通过。真实 Windows 凭据检查按平台跳过。最终 Linux NativeAOT smoke 实际执行通过，加载 5481 个消息定义和 3910 个注册编号；该次执行 134 ms，GC 后托管内存 23,806,400 字节。发布仍有 MemoryPack 已有的 IL2104/IL3053 警告，未将其当成新引入的失败。

## Windows 验证与验收

先同步主程序、ABI 及模型程序集并重启旧宿主，再进行以下验证。

| 场景 | 验收标准 |
|---|---|
| 默认背包模式，A→登录界面→B | A 的目录保留，B 的四类数据只出现在 B 目录；等待 B 身份/背包期间不能继续显示为 A 的有效新更新 |
| 同样切号过程，开启全量模式 | 背包行为与默认模式一致；事件新登录身份未确认前待归属，确认后由 manifest 绑定；结束显示两个玩家的统计 |
| 返回登录界面后停留，再登录 | 捕获继续；不因保留旧密钥就继续确认旧身份，不因停留在登录界面触发身份等待超时 |
| 停止 / 游戏退出 | 网卡停止，事件排空并刷新，最终结果与文件一致；若收尾超过单次 UI 等待，仍显示后台活动，不能另开捕获 |
| 有线转无线 | 重连后继续写当前玩家目录；新连接保留登录上下文但使用独立重组状态，停止后释放接口 |
| 写入错误组合 | 自动用例须通过；实际故障时若事件成功而背包失败，UI 必须展示失败原因，不能仅显示整体成功 |
| 私钥导入 | 真实凭据读写测试通过；现有正确 PEM 仍可捕获，公钥/损坏 PEM 拒绝；无需更换游戏实际使用的 RSA 密钥尺寸 |
| 错误帧和端点碰撞 | 在 Windows 执行自动回归即可，不需要向游戏注入损坏流量；CRC 错误不更新快照，Exception 保留错误码，重复 conv 不串流 |

全量文件继续使用 `tools/validate_game_data_export.py --manifest <路径>` 检查。验收需同时观察整体请求是否成功、事件统计和各玩家快照，不能仅以 manifest completed 判断所有导出模块成功。
